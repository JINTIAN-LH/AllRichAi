# 模块设计

## 目标

将设计文档拆成可以逐步扩展的运行框架，先保证以下六条链路可闭环：

1. 资源链路：播种 -> 成长 -> 收获 -> 销售 -> 微粒/生命源能/资金回流
2. 养殖链路：购入 -> 周期产出 -> 收取 -> 入库
3. 加工链路：原料库存 -> 配方加工 -> 高附加值商品
4. 公司链路：筹备 -> 雇佣 -> 分红 -> 共富指数增长
5. 角色链路：互动 -> 好感提升 -> 任务完成 -> 资源与阶段推进
6. 叙事链路：短期起步 -> 中期产业升级 -> 长期共同富裕

## 目录结构

### `farmgame/models.py`

- 定义全部核心数据结构
- 将作物、角色、技能、任务定义与运行时状态分离
- `GameState` 支持 JSON 存档序列化

### `farmgame/balance.py`

- 集中管理数值平衡参数
- 包含作物成长、系统等级、技能成本、阶段门槛
- 便于后续做数值迭代而不改动引擎代码

### `farmgame/content.py`

- 放置剧情世界观对应的静态内容
- 包括核心角色定义、任务模板、开场文本、阶段结语
- 后续接大模型生成器时，可以把静态模板替换为动态内容源

### `farmgame/engine.py`

- 唯一的规则执行层
- 对外暴露播种、收获、销售、互动、解锁技能、推进天数等操作
- 负责自动结算任务、检测阶段升级、维护最近事件日志

### `farmgame/storage.py`

- 处理本地存档读写
- 当前使用 JSON，后续可以替换为数据库或云存档

### `farmgame/webapp.py`

- 提供 Flask Web 界面入口
- 通过表单操作复用 `GameEngine` 的同一套行为接口
- 使用独立网页存档，避免覆盖 CLI 存档

### `farmgame/validators.py`

- 承担两类校验
- 设计校验：直接审计原始方案中的逻辑冲突
- 运行时校验：验证资金、微粒、生命源能等状态不出现非法值

### `farmgame/app.py`

- 命令行交互层
- 仅做输入输出与菜单调度，不承载业务规则
- 后续可替换为 Web、Ren'Py 或 GUI 前端，保持引擎不变

## 当前模块协作关系

```text
CLI app  -> engine -> models
Web app  -> engine -> models
Ren'Py   -> engine -> models
                -> balance
                -> content
                -> validators
storage <-> models
```

## 已落地的核心状态

- `money`：资金，用于购买种子和衡量经营规模
- `particles`：微粒，系统的基础资源
- `source_energy`：生命源能，用于解锁技能
- `prosperity`：共同富裕代理指标，用于推进终局
- `plots`：农田格子状态
- `pens`：养殖棚舍状态
- `inventory`：仓库库存
- `characters`：角色好感度
- `tasks`：任务完成状态
- `stats`：用于任务和阶段判定的累计统计
- `company`：村办公司状态，包括雇员、品牌、分红比例、储备金

## 为什么保留 CLI 作为底座

- 设计文档目前最完整的是玩法逻辑，不是美术资产和演出细节
- CLI 能最快验证资源循环、任务触发和阶段推进是否成立
- 后续无论接 Ren'Py、Web 还是大模型对话层，都能复用同一套规则引擎
- Web 与 Ren'Py 只是展示层，不应该复制或改写业务规则

## 后续扩展建议

1. 接入大模型意图解析，把自由输入映射到 `engine` 命令
2. 将任务从静态条件改成剧情节点图
3. 引入更多地块属性，例如土壤、季节、天气、设施
4. 把当前加工坊和村办公司升级成可扩展生产线系统
5. 把 `prosperity` 拆分为就业、收入、基础设施、教育四个维度
